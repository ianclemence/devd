# Product review, November 2026

A full pass over devd's interface, its conversations and its agent team, and a trace of
its execution paths (CLI, MCP, the HTTP API and the capability registry). This records
what was found, why it happened, what changed and what is still open, most important
first.

## What was broken, and why

| Finding | Root cause | Fix |
|---|---|---|
| A specialist's conversation (Implementer → Reviewer) did not appear until the page was refreshed | The window dropped every live event for a conversation other than the open one, and re-read the list only when the open conversation stopped | Live events for any conversation or run refresh the list and the run (coalesced, one read per burst); the live channel opens at start, for every screen (`app.js`: `onOtherWork`, `refreshThreadList`, `refreshRuns`) |
| Conversations jumped back up while reading; opened cards closed; screenshots flickered | Every update replaced the conversation's whole HTML: images reloaded at zero height (the scroll position was clamped upward), `<details>` lost their open state; the run view rebuilt every 1.2 s | `morph` patches the conversation and the run in place; browser scroll anchoring is back on; "following the bottom" is decided by the reader's last scroll, not guessed at paint time; a *Jump to latest* pill appears when the reader has scrolled up |
| Every screen took 5-15 s to load | The live channel replayed the entire run history on every connect (one list re-read per past event: `team.list` ×10 per load); every screen waited for `git status` of every project, twelve at once | A new connection starts at the newest event (a reconnect still catches up from `Last-Event-ID`); Git state loads after the list, four at a time, only on screens that show it. Agent Runs went from ~9 s to ~2 s |
| `health.status` ~16-22 s, `toolchain.list` ~18 s, and they slowed every other call | Each call probes the machine (runs executables, opens ports); every screen and poll asked, often at once | `devd_core::memo`: one probe per question at a time, kept a few seconds, discarded the moment any capability changes something (`memo::bump` in the registry) |
| The person's own message was drawn as "Your team" | 0.24.1 drew any message with a sender as a team note; every message has a sender | Only `from: "devd-team"` is a team note; in a specialist's conversation it is devd's brief or devd's note to the member |
| A run finished "done" though its reviewer said "changes needed" | A gatekeeper's report was accepted on the proof that the review happened; its verdict was never read | `verdict_needs_changes`: a reviewer, security or QA "changes needed" adds a fix task for the member who wrote the code and a re-review after it, at most two rounds, then pauses for the person |
| Sites table headings did not sit over their columns; every cell repeated its heading | The heading and each row were separate grids (the empty action column made the heading's columns wider); the "Serves:" labels applied at every width | One grid for the table, rows on `subgrid`; labels only on narrow windows where the heading is hidden |
| Assistant and Agent Runs unusable below 1000 px | Two narrow-width rules contradicted each other and put the list header beside a vertical list | The list moved into the navigation's context panel, which folds into an overlay below 1024 px |

## What changed in the interface

- **Graphite and one blue.** True neutral surfaces in four steps, three text greys, one accent; status colours only beside a word.
- **Navigation: rail, context panel, page.** The top bar, the section-tab bar and the per-page lists are one system. The panel lists an area's pages and the things in it (each project, each site), or the conversations and runs, grouped by project, with every specialist nested under the request it works for. Phones get a bottom bar with a More sheet.
- **Conversations read as a team at work.** Each role has its own mark (an icon on a tint, never a letter); step lines say what was done to what ("Read Meetup.php", "Ran test … · 41 passed"); edits show their diff; a finished turn folds its work behind "Worked for 12m 55s" with result tiles; the project card beside a conversation shows the branch and changes.
- **The run view is a conversation**, oldest first, with handoffs written as handoffs.
- **One type scale and one icon weight.** Seven sizes, each with a job; the sprite's strokes are non-scaling, so a 12 px chevron and an 18 px rail icon carry the same 1.5 px line.
- **Callouts** (notices, banners, toasts, dialogs) are one family: a quiet surface, a toned icon, the action at the end of the line.

## Agents

- Agents narrate: before each batch of tool calls, one sentence of what and why (assistant and team prompts).
- Built-in skills: `agent-browser` and `agent-desktop` (adapted from Vercel Labs, Apache 2.0), with the CLIs in the tool catalogue.
- Tool catalogue: FFmpeg, HyperFrames, agent-browser, agent-desktop. Skills page: one-click HyperFrames and Stageshow.

## Verified

- Every read capability (167) called with no arguments: 74 answered, 89 asked for their missing argument by name, 4 reported an absent service with the command to install it. No crash, hang or 500.
- Every write capability with a dry run (197): each planned or asked for arguments; none executed.
- MCP over stdio: initialise, list tools, invoke; an agent asking for a human-only operation is refused; an agent writing outside its projects is refused with what to do instead.
- Every read-only CLI command against a copy of the home.
- Live update: a conversation created elsewhere appears in an open Assistant in about 3 s, with no refresh.
- 130 screens at 1600, 1280, 1024, 800 and 390 px, before and after.

## Still open, by impact

1. **The machine probes are slow at the source.** Caching hides it from the window, but `health.status`, `doctor` and `toolchain.list` still take 5-25 s cold. The probes run executables one after another; running independent probes in parallel is the real fix.
2. **Reads are audited.** Every window read writes an Activity row (by design: Activity has an "everything, including reads" view). Polling is now far less frequent, but a window open all day still writes thousands of rows.
3. **90 write capabilities have no dry run**, so neither a person nor a test can see their plan without running them.
4. **The definition of done is machine-checked only when a judge is configured.** Without one, a run can finish on passing tests alone; the reviewer verdict now catches the common case.
5. **The team commits nothing.** Work is merged into the working tree uncommitted; a run should end on a commit (or a branch) the person can review.
6. **No agent-native production loop yet.** Deploy, monitor and respond exist as capabilities (`deploy.*`, `monitor.*`, `observe`), but no standing team watches a live site and opens a run when it breaks. This is the largest step toward "give devd an objective and trust it".
