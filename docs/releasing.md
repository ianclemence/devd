# Releasing

`devd` is released from a developer machine. CI builds, lints and tests the
workspace on Windows, Linux and macOS, but there is no automatic release or
publication: a release is a deliberate sequence of local commands, and an
artifact is only attached after it has run on the platform it targets.

## The rule

A binary is published only if it has been executed on that platform. The release
scripts enforce it: each one builds the binary, runs it, checks the version it
reports, exercises the capability registry, and only then copies it to `dist/`.
A build that cannot be run is not a release artifact.

## Version

The version lives in one place, `Cargo.toml`. Every crate inherits it, and
`devd --version` reads the compiled value. Bump it and add the version's section to `CHANGELOG.md` before building;
that section is also the release body.

## Windows

```powershell
.\scripts\release-windows.ps1            # tests, build, smoke test, checksum
.\scripts\release-windows.ps1 -SkipTests # when the suite has just been run
```

Output:

```text
dist/devd-v<version>-x86_64-pc-windows-gnu.exe
dist/devd-desktop-v<version>-x86_64-pc-windows-gnu.exe
dist/devd-desktop-v<version>-x86_64-pc-windows-gnu.zip
dist/SHA256SUMS.txt
```

`devd-desktop.exe` is the native Tauri shell and contains its own backend; it
does not need the CLI binary at run time. It does need `WebView2Loader.dll` in
the same directory, which is why the zip carries both. Building it needs the
WebView2 headers used by Tauri, which the Rust crates provide, and a C compiler
for SQLite.

The installer is a second artifact:

```powershell
.\scripts\release-installer.ps1
```

It rebuilds both release binaries, then compiles `installer/devd.nsi` into
`dist/devd-setup-<version>.exe` and rewrites the checksum file. The installer
places `devd.exe`, `devd-desktop.exe`, the launcher, shortcuts and the
uninstaller under `%LOCALAPPDATA%\Programs\devd`. NSIS 3 is required; pass
`-Nsis <path to makensis.exe>` when it is not at the default location.

The installer must be exercised, not just built: install it, let the finish page
run `devd setup`, check the Start Menu shortcut opens the native window, exercise
Agents, Processes, Shared and a site's Preview tab, then uninstall it. The per-user install and
its uninstaller are both reversible without administrator rights.

The binary is built for `x86_64-pc-windows-gnu` with `rust-lld`, as configured in
`.cargo/config.toml`; it links only Windows system libraries, so it needs no
Rust toolchain, MinGW or Visual C++ runtime at run time. It is not code-signed,
which is why the checksum is published next to it.

## Linux

On any Linux machine, or inside WSL or a Linux container:

```bash
./scripts/release-linux.sh
```

It runs `cargo test --workspace`, builds the release binary, runs it against a
temporary home, and writes `dist/devd-v<version>-<host-triple>` plus its
checksum. It needs `rustc`, `cargo`, a C compiler for the bundled SQLite, and
coreutils.

From Windows, the same build can be driven through a local Linux environment:

```powershell
.\scripts\release-linux.ps1                  # first WSL distribution, or Docker
.\scripts\release-linux.ps1 -Distro Ubuntu
.\scripts\release-linux.ps1 -DockerImage rust:1-bookworm
```

The wrapper copies the source into the Linux filesystem (a build over the
Windows drive is several times slower), runs the script there, and copies
`dist/` back. It exits non-zero with instructions when neither WSL nor Docker is
available.

## Publish

```bash
git tag v<version>
git push origin v<version>

gh release create v<version> \
  --title "v<version> - M<n>: <summary>" \
  --notes-file release-notes.md   # the version's section of CHANGELOG.md

gh release upload v<version> dist/*
```

Then verify what a user would get:

```powershell
curl.exe -LO https://github.com/ianclemence/devd/releases/download/v<version>/devd-setup-<version>.exe
curl.exe -LO https://github.com/ianclemence/devd/releases/download/v<version>/SHA256SUMS.txt
certutil -hashfile devd-setup-<version>.exe SHA256
```

The hash must match, and running the installer from that download must produce a
working application. The standalone binary is verified the same way: hash, run,
`devd --version`.

```bash
gh api "repos/ianclemence/devd/releases?per_page=3"
```

returns the three most recent releases, which is the document the update check
will read when it exists.

## Checklist

1. `Cargo.toml` version bumped; `Cargo.lock` regenerated by the build.
2. `CHANGELOG.md` has an entry for the version.
3. Documentation updated: `README.md`, `docs/limitations.md`, `docs/security.md`
   and `docs/architecture.md` where the release changed what they describe.
4. `git status` clean after committing, `git push origin main` done.
5. Artifacts built and executed on each platform being published.
6. Tag created and pushed, release published, assets uploaded.
7. The release body is the CHANGELOG section; `gh release edit` after any
   later correction.
8. The download and checksum steps above were actually performed.
