# v0.7.0 — agents in the window, and a built-in browser

devd is now the place where the work happens: the services run, the site
renders, and the coding agent you already use runs in the project — all in one
window.

```text
WORKSPACE          SERVER
  Projects           Overview
  Agents             Sites
  Capabilities       Preview
  Activity           Services
  System             Runtimes
                     Certificates
                     Hosts
```

## Run your agent inside the project

**Agents** detects the harnesses installed on this machine — Claude Code,
OpenCode, or a plain shell — and starts the one you pick in a project
directory. The terminal is a real PTY: the harness draws its own interface,
keeps its own account and model, and asks its own permission questions.

devd supplies the directory, the terminal and the process. It does not proxy the
model, store the conversation, or stand between the harness and its provider.
That is why a new model or harness feature works the day it ships, and why the
agent's permission prompt is still the thing that decides what it may touch.

Harness cards say **not installed** rather than failing when the CLI is missing.

## See the site you are building

**Preview** embeds the running site in the window, with a site picker, reload,
and open-externally. The certificate authority has to be trusted for an HTTPS
site to render without a warning; the page says so when it is not, and links the
trust action.

The iframe is sandboxed: scripts and forms work, but the previewed page cannot
navigate the window that contains it. A site that sends `X-Frame-Options` or a
`frame-ancestors` policy will refuse to embed; devd's generated vhosts do not.

## A warmer window

The blue-grey dashboard palette is gone. The window uses warm graphite surfaces
and one terracotta accent, larger page titles, and a quieter rail. The agent
terminal uses the same palette, so the harness looks like part of the tool
rather than a black rectangle dropped into it.

## How it is wired

| Piece | What it does |
| --- | --- |
| `portable-pty` | Opens a real console per agent, with resize support. |
| `xterm.js` (MIT, vendored) | Renders the terminal in the window. |
| `/api/terminal/harnesses` | Reports which CLIs are installed. |
| `start` / `output` / `input` / `resize` / `stop` | Poll-based transport behind the same bearer token as every other endpoint. |
| `frame-src http: https:` | The only CSP widening, for the preview only. |

## Known limitations

One terminal at a time; reloading the window loses its handle while the PTY
keeps running. Output is polled at 80ms and kept in memory, not archived. The
agent's own prompts are the authority for what it may edit or run — devd does
not mediate those.

## Install

Windows: run `devd-setup-0.7.0.exe`. Linux: build from source, or produce an
artifact with `scripts/release-linux.sh`. The installer upgrades in place and
keeps your sites, services and data.
