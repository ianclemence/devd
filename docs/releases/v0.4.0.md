# v0.4.0 — M3: the terminal dashboard

```bash
devd tui
```

`devd` now has a fourth way in, and it is the one that works where the others
cannot: a console with no browser to open it, or an SSH session with nothing
forwarded. It is the third projection of the same registry — the CLI, the
application window, the MCP server and now the dashboard all read the same
capability declarations and all write through the same dispatcher.

```text
 devd 0.4.0  C:\devd  git 2.46.0.windows.1
 1 Dashboard  2 Projects  3 Changes  4 History  5 Branches  6 Capabilities  7 Activity  8 Doctor  9 Help
 ┌ Changes - main: 1 staged, 2 unstaged, 1 untracked in C:/code/devd ──────────────┐
 │M staged     README.md                                                           │
 │M unstaged   README.md                                                           │
 │M unstaged   crates/devd-core/src/lib.rs                                         │
 │? untracked  NOTES.md                                                            │
 └─────────────────────────────────────────────────────────────────────────────────┘
  Enter stage/unstage   s stage   u unstage   d discard   a stage all   c commit   r refresh   ? help   q quit
```

That is a real frame from a real repository, not a drawing. Nine views: the
dashboard, projects, changes, history, branches, the whole capability registry,
the audit trail, the doctor, and the key map.

## The keys that change something are the same operations

`s` stages, `u` unstages, `a` stages everything, `c` commits, `Enter` toggles a
file in or out of the index, `n` creates a branch, `t` tracks a repository, `x`
runs any capability in the registry with arguments you type.

`d` discards the selected file, and discarding is `Tier::Destructive`, so the
dashboard **does not discard it**. It asks the registry for the plan and shows
it:

```text
 ┌ Confirm a destructive operation ────────────────────────────────────────────────┐
 │ git.discard needs your decision before it runs                                  │
 │                                                                                 │
 │ discard uncommitted changes in 1 path(s)                                        │
 │   - files: README.md                                                            │
 │   - 1 of these currently differ from HEAD                                       │
 │   - this content is NOT recoverable from Git; it was never committed             │
 │                                                                                 │
 │ arguments                                                                       │
 │ {"paths":["README.md"],"repo":"C:/code/devd"}                                   │
 │                                                                                 │
 │ y approve and run       n decline, and record the refusal                        │
 └─────────────────────────────────────────────────────────────────────────────────┘
```

The three lines in the middle are `git.discard`'s own words. The dashboard does
not summarise them, and it does not rebuild the request afterwards: it keeps the
one it built, shows the plan for it, and replays *that* on `y`, so what you read
is what runs. `n` does not just close the prompt — it dispatches the same request
as refused, the registry refuses it, and the refusal lands in the audit trail
labelled `refused`, exactly as the CLI's does.

A branch switch that would overwrite local work becomes the same kind of
confirm, and the list of files at risk comes from `git.switch.check` — the
product's own check, not a second opinion invented for the dashboard.

## It refuses to start without a terminal

```console
$ devd tui < /dev/null
devd: unsupported: the dashboard needs an interactive terminal (use `devd ui` for
the window, `devd serve` for the API, or `devd capabilities` for the list)
$ echo $?
2
```

Entering raw mode on a stdout that is a pipe is not something crossterm can
report on Windows: there is no console handle to switch, and the call took the
process down with `0xc0000005`, no output, and no way to tell the user why. A
refusal with a reason and a way forward is the correct behaviour for a surface
that cannot do its job, and a test asserts it.

## Escape sequences in branch names cannot reach your terminal

A branch name or path containing a control character is not text at that point,
it is a command being sent to the reader's terminal. Every string that reaches
the screen goes through one function that replaces control characters, and a test
renders a branch named `evil\u{1b}[2Jbranch` and asserts that no escape reached
the buffer.

## Tests

**226 tests pass** (up from 169), zero warnings, run with `cargo test --workspace`
and again with `--release`.

The 57 new ones are in `devd-tui`:

* **52 unit tests** drive the controller with real keystrokes against a backend
  that *counts what ran*, so the claims above are measurements: a destructive key
  runs nothing until `y`; `n` runs nothing and sends the refusal; `Esc` on a
  prompt does not leak the keystroke to the view behind it; an empty commit
  message never reaches Git; bad JSON arguments are reported rather than
  attempted; an unsafe switch becomes a confirm.
* **5 integration tests** build the real registry over a throwaway repository,
  track it through `git.repo.track`, and drive the dashboard down the same code
  path the binary uses — including staging from the dashboard actually changing
  the index, and `d` followed by `n` leaving the file on disk with a refusal in
  the audit table.
* **Every frame is rendered, not described.** The view tests draw into
  `ratatui`'s `TestBackend` and assert on the buffer, so a frame that stops
  showing the branch, the plan or the choice fails a test instead of reaching a
  person. Both transcripts above were produced that way.

## A build fix worth recording

While writing this, the release binary began crashing at startup with
`0xc0000005` — in its own code, before `main`, with no output. Debug builds were
fine, `cargo test` was fine, and the same source linked by Rust's own linker was
fine; the difference was that the final `devd` link on this GNU host goes through
a `cc` that forwards to Zig. `.cargo/config.toml` now pins
`linker = "rust-lld"` for `x86_64-pc-windows-gnu` only, with the reason written
next to it. Nothing else changes: C sources are still compiled by `cc`, and
anybody building with MSVC is unaffected.

## Still not built

The runtime installers, the services (nginx, Apache, MySQL/MariaDB, Redis,
Mailpit), sites and virtual hosts, DNS, automatic HTTPS, SSH control of a remote
host, snapshots, and the in-app conversational agent. The Services, Sites and
Runtimes panels say plainly that they are not implemented rather than offering
switches that do nothing. The full list, with the consequence of each gap, is in
[`docs/limitations.md`](https://github.com/ianclemence/devd/blob/main/docs/limitations.md).

## Install

```bash
git clone https://github.com/ianclemence/devd.git
cd devd
cargo build --release
./target/release/devd tui
```

Requires Rust and `git` on `PATH`. Source archives only; no third-party
binaries.

See [`docs/tui.md`](https://github.com/ianclemence/devd/blob/main/docs/tui.md)
for the dashboard, and
[`docs/architecture.md`](https://github.com/ianclemence/devd/blob/main/docs/architecture.md)
for how the four surfaces stay one product.
