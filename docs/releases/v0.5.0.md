# v0.5.0 — M4: a real site over HTTPS

```bash
devd runtime install php
devd service install nginx
devd site create blog
devd stack up
```

Four commands, and `https://blog.test` is served by nginx, executed by PHP as
FastCGI, over TLS with a certificate chain that verifies against `devd`'s own
authority. That is the milestone: not a design, a site.

```console
$ devd service list

  mariadb 13.0.2   running  pid 7772   port 3307
  nginx   1.31.7   running  pid 11764  port 8080, 8443
  php-cgi 8.3.35   running  pid 14096  port 9000

$ openssl s_client -connect 127.0.0.1:8443 -servername demo.test \
    -CAfile certs/devd-ca.crt -verify_return_error -brief

Ciphersuite: TLS_AES_256_GCM_SHA384

$ curl --resolve demo.test:8443:127.0.0.1 https://demo.test:8443/
```

The ports are 8080/8443/3307 rather than 80/443/3306 because this machine
already had an Apache and a MySQL listening on the defaults. Ports are settings,
and `devd` reports which process holds one instead of failing obscurely.

## Runtimes

`devd runtime install php|node|go` reads the vendor's own catalogue —
`windows.php.net`'s `releases.json`, `nodejs.org/dist/index.json` with its
`SHASUMS256.txt`, `go.dev/dl/?mode=json` — picks a build, downloads it in-process
with `ureq` and `rustls`, checks the published digest, extracts it, and verifies
what it installed by running it.

PHP is the interesting one. The zip ships extensions that cannot load on the
machine they were built for, so `devd` enables a curated list intersection what
the build actually contains, runs the interpreter, reads its warnings, comments
out anything that reports "Unable to load dynamic library", and runs it again.
`opcache` is enabled as a `zend_extension`, because that is what it is. The
install reports which extensions were enabled and which were switched back off.

Nothing is bundled and no external `curl` is used. The digest is the check;
published sizes are rounded, so size gets a 5% tolerance and the digest decides.

## Services

`devd service` installs, starts, stops, restarts, lists, reads logs from and
removes nginx and MariaDB. `devd web render|test|reload` drives the web server
directly, `devd stack up|down` brings the whole stack up in dependency order
(`php-cgi`, then `mariadb`, then `nginx`), and `devd db create|list|drop` talks to
the server through its own client.

* **A start is verified, not assumed.** The port is polled until it opens or the
  service's own startup window expires (nginx 10s, MariaDB 60s, php-cgi 10s). A
  failure kills the process, closes the run row as failed, and returns the tail
  of the service's own log.
* **Services outlive the command that started them**, and ownership is recorded
  in a pid file whose pid is checked against the process image, so a recycled
  Windows pid never makes `devd` kill a stranger.
* **`php-cgi` is not a download.** It is the `php-cgi.exe` of the primary PHP
  runtime, turned into a service row on demand by `service start php-cgi`, by
  installing nginx, or by `stack up`.
* **`nginx.conf` is generated output.** The site table is the source of truth;
  the renderer writes the whole file, including the PHP upstream, the
  default-server 404 and the access/error log per host.

## Sites, TLS and hosts

`devd site create blog` makes the directory, writes a starter page, finds the
primary PHP runtime, issues a certificate and renders the vhost. It prints the
URL. It does **not** touch the hosts file: publishing a name is `hosts.sync`, a
separate `Tier::Admin` capability that snapshots the file first, preserves every
line outside its own marked block byte for byte, and is idempotent.

TLS is issued in-process by `rcgen` from an internal ECDSA P-256 authority
created on first use. The leaf is written as a full chain for nginx, valid 397
days, backdated an hour; the CA is valid ten years and its key is never returned
by a capability or written to a log. `devd tls trust` puts the CA in the
operating system's trust store — `certutil -addstore` on Windows, `trust anchor`
on Linux — and is `Tier::Admin`, so it needs a human.

## MariaDB

MariaDB is installed from the vendor's archive and initialised with its own
`mysql_install_db.exe`, without registering a Windows service. Data lives in
`etc/mariadb/data`, outside the install directory, so removing the binaries
keeps the databases and says where they still are. It binds `127.0.0.1`, uses
`utf8mb4`, `STRICT_TRANS_TABLES`, and `root@localhost` has no password by
default — the install prints that as a warning, and
`DEVD_MYSQL_ROOT_PASSWORD` sets one at first initialisation. The password reaches
clients through `MYSQL_PWD`, never `argv`, and is never written to a file.

MariaDB's catalogue comes from its release API rather than its archive listing,
because the listing offers preview series and stable releases that shipped no
Windows package. Only Stable series with a `winx64.zip` are offered, each with the
per-file SHA-256 the API publishes.

## Bugs found by running it

Every one of these was found by using the product, not by reading it:

* **Certificates were written under the wrong name.** Paths were built with
  `Path::with_extension`, which replaces everything after the last dot:
  `certs/blog.test.crt` became `certs/blog.crt`. nginx was told to load a file
  that did not exist and refused to start. Paths are now built from the whole
  file name, and a test asserts the exact leaf paths.
* **A detached service kept the shell's pipe open.** `devd stack up | Tee-Object`
  printed its result and then hung until the harness killed it, because nginx had
  inherited `devd`'s stdout. `process::isolate_standard_handles` clears the
  inheritance flag on `devd`'s own handles before spawning; the same command now
  returns in 1.5s.
* **The debug build could not print `--help`.** Windows reserves 1 MB for the
  main thread, and the grown command line's clap frame outgrew it in an
  unoptimised build. `.cargo/config.toml` raises the reserve to 8 MB for this
  target, matching what Linux already gives the main thread.
* **`mysql_install_db.exe` has no `--basedir`**, and said so with exit code 7.
  The flag was removed; `--port` was added.
* **`mysql --batch` prints a header row**, which made `schema_name` appear as a
  database in `db list`. The client is now called with `--skip-column-names`.
* **The MariaDB catalogue resolved `latest` to a preview with no Windows
  package.** It now reads the release API.
* **The install's MariaDB report was collected and dropped**, so the data
  directory, whether it was initialised and the password warning never reached
  the user. They are part of the install result now.

## Tests

**318 tests pass**, zero warnings, with `cargo test --workspace`.

The new ones cover the parts that are hard to see: that a generated vhost names
the certificate files that exist, that the hosts block preserves foreign lines and
CRLF endings and is idempotent, that a hostname with a directive in it is refused
before anything is written, that a removed site outside the `www` root is refused,
that the TLS chain verifies against the CA and that a second issuance replaces
the leaf without replacing the CA, and that MariaDB's `my.ini` is what the process
is then started with.

The live network paths are `#[ignore]` tests rather than part of the default run:
they download ~33 MB of PHP, ~30 MB of Node, ~80 MB of Go, ~2.8 MB of nginx and
~104 MB of MariaDB. They were run here, by hand, and the results are the
transcript above.

## Still not built

Apache, Redis and Mailpit; a DNS server (names resolve through the hosts block,
one entry per site); SSH control of a remote host and deploy; snapshots beyond the
hosts write; the self-update check; and the in-app conversational agent. The
application window and the dashboard do not yet have Runtimes, Services or Sites
panels — the capabilities are there and the CLI covers them, but a dedicated
screen is a screen. On Linux there is no service provider yet, because the
vendors' archives in this milestone are Windows ones.

The full list, with the consequence of each gap, is in
[`docs/limitations.md`](https://github.com/ianclemence/devd/blob/main/docs/limitations.md).

## Download

**Windows x86_64** — a prebuilt binary is attached to this release:

```powershell
curl.exe -LO https://github.com/ianclemence/devd/releases/download/v0.5.0/devd-v0.5.0-x86_64-pc-windows-gnu.exe
curl.exe -LO https://github.com/ianclemence/devd/releases/download/v0.5.0/SHA256SUMS.txt
certutil -hashfile devd-v0.5.0-x86_64-pc-windows-gnu.exe SHA256
```

`SHA256SUMS.txt` contains
`2ab0f61183e739bca94e03cb4485bc075820c8e040ccab94bc2381146d25e686`.
Rename the file to `devd.exe`, put it on `PATH`, run `devd doctor`. It needs no
Rust toolchain and no redistributable runtime — only Windows' own DLLs — and it
is not code-signed, so SmartScreen will warn once.

**Linux x86_64** — build from source. No Linux binary is attached, because this
release was built and tested on Windows and a cross-built executable could not be
run before publishing:

```bash
git clone https://github.com/ianclemence/devd.git
cd devd
cargo build --release
./target/release/devd doctor
```

Requires `rustc`/`cargo` and a C compiler; SQLite is compiled in. Nothing is
bundled: PHP, Node, Go, nginx and MariaDB are downloaded from their vendors on
first use and verified against the digest the vendor publishes — except nginx,
which publishes only a signature, and whose install says so.

See [`docs/architecture.md`](https://github.com/ianclemence/devd/blob/main/docs/architecture.md)
for how the four surfaces and the new skill crates stay one product.
