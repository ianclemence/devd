# v0.9.0 - a folder picker, official brand marks, and a stylesheet that works

devd now lets you find a project by looking at your device instead of typing
its path, shows the owners' own marks beside the services and model providers
it supports, and — after a one-character fault in the stylesheet — actually
adapts to the window you are in.

The investigation behind this release is in `docs/research/`: what Laravel
Herd 2.0.2 actually does and the evidence for it, a feature acceptance matrix
mapping every Herd capability to its devd equivalent, a full screen inventory,
and the comment audit that is waiting for a decision.

## Choosing a project by looking at your device

Adding a project used to mean typing a path. It no longer does, anywhere.

* The **desktop window** opens the **operating system's own folder dialog** -
  the same Windows picker Laravel Herd uses, with the same shape: a title, a
  tree, a folder field and a "Select Folder" button. It is opened by the shell
  and returns a path and nothing else: it cannot read a file, run a program or
  reach the registry.
* The **web application** draws its own folder browser, because a page in a
  browser cannot open a native dialog. It lists the places work is kept, the
  filesystem roots, the path as a trail you can step back through, and the
  folders that are there - with symbolic links marked as links.
* The folder you highlight is **inspected before you commit to it**: the
  detected stack and how sure it is, the package manager, the runtimes the
  project asks for, whether it is a Git repository, the environment variables
  it expects, and anything missing.
* The same picker is used wherever a folder is needed: the Projects screen, the
  Develop tab, the agent's working directory, and the destination for a clone.
* In a **terminal**, `devd project browse [path]` prints the same listing and
  marks the directories that hold a project.

A new `fs.browse` capability does the listing, so the window, the terminal and
an agent all see the same disk. It handles Windows drives, UNC paths, the
verbatim `\\?\` prefix, long paths, non-ASCII names, and a directory that
cannot be read - which is reported, not hidden.

## One list of projects

There were two lists of projects, and a project could be in one and not the
other. `project.list` now returns the union of the projects devd imported and
the repositories it indexed, sorted by name, and the window, the terminal and
an agent all read that one list.

"Remove from devd" and "Delete from disk" are now different things, with
different words and different consequences. The first forgets a project and
keeps the folder. The second deletes the folder and asks you to type its name
first.

## Official brand marks

Fifty-one marks - the model providers, the databases, caches, search engines,
runtimes, tools and editors - now appear beside the things they name. Each one
is the owner's own artwork, taken from their own site or from a curated brand
registry, served from the binary, and never recoloured or distorted.

Anthropic, OpenAI, DeepSeek, Moonshot AI, Zhipu AI, Google Gemini, xAI,
Mistral, Groq, Together, Fireworks, OpenRouter, Ollama and LM Studio all have
theirs. So do MySQL, MariaDB, PostgreSQL, MongoDB, Redis, SQLite, nginx, PHP,
Node.js, Composer, Laravel, TypeSense, Mailpit, Xdebug, Docker, Git and more.

A mark is never shown for something devd cannot reach, and a supported thing is
never left unmarked when the owner publishes a mark. Where the owner publishes
a wordmark rather than a square one, it is given room to be read rather than
being squashed.

## The stylesheet that works

A malformed rule left a brace open, so the browser silently ignored everything
after it: **the bottom half of the stylesheet, including every responsive
breakpoint**. The application was laid out for a wide window and fell apart
below 960 pixels, and nobody had noticed, because the fault was in the file and
not in the browser.

Measured after the fix, from 1536 pixels down to 320: the rail is 244 pixels
wide, narrows to 224, becomes an icon rail at 960 and a top strip at 720, and
there is no horizontal overflow at any width.

## Corrected along the way

* `git.reflog` returned lines of text where the interface expected structure,
  so the Recover tab showed blank rows and offered to reset to an empty
  revision. It now returns the hash, the reference, the time, the action and
  the subject.
* A provider whose id was not a preset id could not be edited: the interface
  sent the provider's own id as a preset, and the server refused it.
* "Dry run" on a capability that cannot plan threw an error. It now says so.
* Untracked and conflicted files shared a badge, and the same file was red on
  one screen and green on another.
* A failed request for the activity log looked like an empty history.
* The Diagnostics screen claimed that services, sites, runtimes, DNS and
  certificates had no capabilities - on the same screen that renders all five.
* The number of stacks was written into the interface. It now comes from the
  server.
* The `hidden` attribute hid nothing that had a `display` rule of its own.
* The runtime installer dropped its "upstream publishes no digest" warning,
  because a later binding shadowed it.
* `devd setup` aborted on Linux, where devd publishes no PHP or service
  binaries. It now uses the system's own PHP and services, says so, and reports
  what is left to do instead of failing.
* The activity log and the capability registry were unbounded. Both are paged,
  with a real count of what is showing.
* The same screen had two names in two places. There is one name per
  destination now, in the rail, the tabs, the command palette and the
  breadcrumb.

## Installing and removing

The Windows installer can be **repaired** - re-running it over a broken install
is the cheapest way to fix one, and it stops the running copy before it writes.

The uninstaller now **says what it keeps**. Your projects, databases,
certificates and settings stay in `%LOCALAPPDATA%\devd` unless you tick the box
that removes them.

There is a **Linux installer** now: a per-user install with no administrator
rights, a desktop entry, and an uninstall that keeps your data unless you ask
it to remove it.

## What is still missing

The honest list is in `docs/limitations.md`. The largest gaps are the
services devd does not install itself - PostgreSQL, MySQL, Redis and MongoDB
are found on the machine and can be driven through your system package
manager, but devd installs and supervises only nginx and MariaDB - and the
local mail server, the dump interception, the Xdebug session capture and the
public tunnel, none of which exist yet.

A permission divergence found during the audit - the HTTP API dismissing an
agent session without the approval that its own capability demands - is
documented in `docs/research/00-comment-debt.md` and is waiting for a
decision before it is changed.
