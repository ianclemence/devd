# M0 — the foundation, and a complete Git integration

The first milestone. It delivers the part of the product everything else will be
built on — **the capability registry and its permission model** — together with
one skill area, **Git**, implemented end to end so that the model is proven
against a real, stateful, destructive domain rather than a toy one.

## What is in this release

**`devd-core` — the core**

A capability carries an id, a group, a summary, a description, a permission tier,
a side-effect class, a JSON Schema generated from the same Rust struct the
handler deserialises, and flags for dry-run support, agent safety, human-only
reservation, idempotence and reversal. One dispatcher is the only path to a side
effect, and it enforces, in this order:

1. the capability exists;
2. the operator declined — a decline is final;
3. the human-only reservation — checked **before** approval, so an approval
   cannot unlock an operation for an agent;
4. the agent-safety reservation;
5. the tier's approval requirement;
6. dry-run support;
7. run, then record.

Everything is audited, including refusals, and argument objects are redacted
before they are written.

**`devd-git` — 64 capabilities in 12 discoverable groups**

`git.repo`, `git.changes`, `git.commits`, `git.history`, `git.branches`,
`git.tags`, `git.remotes`, `git.merge`, `git.stashes`, `git.worktrees`,
`git.config`, `git.recovery`.

The typed service drives **the user's own `git` executable** through `argv`
arrays. Rebase, bisect, worktrees, submodules, LFS, credential helpers, hooks and
the index format are only faithful when Git itself performs them.

Safety properties that are structural, not procedural:

- **Force push is a separate capability**, not a flag, so no code path can build
  a forced update without its own approval gate. A test asserts the ordinary push
  schema has no `force` property.
- **Both push capabilities are Remote-tier**, so publishing to a machine `devd`
  does not own needs a human.
- **A remote URL that embeds a password is refused**, because such a URL is
  written to `.git/config` in plain text.
- **Configuration keys that exist to hold a credential are refused**, as is
  turning off `http.sslVerify`.
- **`git.config.set` is human-only**: a Git config file can name a program to
  run, so writing one is not a benign operation.
- **No capability accepts a command line.** There is no general-purpose
  `run_command`, and therefore no escape hatch to lower into.

**`devd-cli`**

`capabilities`, `describe`, `call`, `audit`, `doctor`, and a Git command set that
keeps Git's vocabulary: `status`, `diff`, `stage`, `unstage`, `discard`,
`commit`, `log`, `branch`, `switch`, `fetch`, `pull`, `push`, `clone`, `merge`,
`stash`, `worktree`, `remote`, `tag`, `conflicts`, `continue`, `abort`, `reflog`,
`undo`, `revert`, `reset`, `cherry-pick`, `rebase`, `squash`, `bisect`, `repo`.

Interactively you are shown a plan — repository, branch, target, affected files —
and asked. Non-interactively the command prints the plan and exits `3` rather
than guessing; `--yes` is the deliberate form. Exit codes are stable: `2` invalid,
`3` approval required or denied, `4` not found, `5` conflict.

## Tests

**99 tests, all passing**, run locally — there are no CI workflows in this
repository, by decision. Reproduce with `cargo test`.

| Suite | Count | What it covers |
| --- | --- | --- |
| `devd-core` unit | 43 | The registry: an agent cannot perform a human-only operation, a declined operation never executes, secrets are redacted from the audit trail. |
| `devd-git` unit | 10 | Revision, ref, path and remote-URL validation, option-injection refusal, redaction, the credential-key rule, the certificate-verification rule. |
| `devd-git` lifecycle | 30 | Real repositories: the whole Git lifecycle, hunk staging, amend, branches, rebase, autosquash, squash, conflict detection, resolution, abort and recovery, reset modes, the stash lifecycle, the worktree lifecycle, tags, cherry-pick, revert, clone, fetch, pull, push, force-push-with-lease recovery, a diverged pull, credential rejection, an unreachable remote, ignore rules, paths with spaces. |
| `devd-git` policy | 16 | The real dispatcher: declined operations do not run, approval is required then honoured, an agent cannot self-approve, a denied operation cannot be reached through a different capability, a dry run changes nothing, destructive plans name what they destroy, every attempt is audited with its actor and surface, secrets never reach the audit trail, a resolved conflict continues through the registry. |

Two of these found real inconsistencies rather than confirming the design: a plan
could declare itself destructive while claiming no approval was needed, and a
configuration write could have disabled certificate verification. Both are fixed.

Three real Git bugs were found by test: `git branch -b` does not exist (creating
and switching is `git switch -c`), `switch_safety` compared the merge base
instead of the two commits so a dangerous switch looked safe, and `%1f` is
literal in `git stash list` where `for-each-ref` accepts it.

The properties worth naming explicitly, because they are asserted rather than
described:

- A declined `git.discard` does **not** run, and the file is byte-for-byte what it
  was.
- Aborting a conflicted merge or rebase restores the previous state **and**
  preserves uncommitted work in files the operation did not touch.
- Nothing is staged by a dry run of `git.stage`.

## Known limitations

This is **M0**. Read [`docs/limitations.md`](https://github.com/ianclemence/devd/blob/main/docs/limitations.md)
before relying on it.

- **Only the Git capability group is registered.** The service, site, DNS, TLS
  and runtime capabilities are designed but not implemented.
- **There is no TUI, no desktop GUI, no HTTP API and no MCP server yet.** The
  capability declarations and JSON Schemas they need already exist.
- **No macOS.** Windows and Linux are the targets.
- **Windows process-tree termination uses `taskkill /T /F`**, not a Job Object, so
  children are not guaranteed to die if the daemon is terminated abruptly.
- **No network remote fixture in the test suite.** Remote synchronisation is
  exercised against local bare repositories and `file://` URLs; failure is
  exercised against a loopback address that refuses the connection.
