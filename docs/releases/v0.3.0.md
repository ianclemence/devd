# v0.3.0 — M2: the agent surface

`devd` now speaks the Model Context Protocol.

```bash
devd mcp --client claude-code
```

```json
{ "mcpServers": { "devd": { "command": "devd", "args": ["mcp", "--client", "claude-code"] } } }
```

It is the third projection of the same registry, after the CLI and the
application window, so an agent driving `devd` reaches the same functions as a
person with the same permission checks.

## Five discovery tools, not sixty-four

Publishing one MCP tool per capability is the design that gets worse as the
product gets better. With 64 Git capabilities today — and services, sites,
runtimes, DNS and TLS still to come — the list would be hundreds of entries,
loaded into every conversation whether or not it is relevant.

Instead the server publishes tools that read the registry:

| Tool | Purpose |
| --- | --- |
| `devd_groups` | The domains, and how many capabilities each holds |
| `devd_capabilities` | Search by text, by domain, or both |
| `devd_describe` | One capability, with the JSON Schema of its arguments |
| `devd_invoke` | Run one by id, optionally as a dry run |
| `devd_doctor` | The environment check |

A capability added tomorrow is discoverable immediately. A test asserts that two
servers over registries of different sizes publish an identical tool list.

## An agent cannot approve its own operation

The MCP server **discards** the actor it is handed and installs an agent actor,
because a claim is not evidence. An operation in a tier that requires approval is
refused and written to the audit trail; `human_only` is refused before approval is
even considered.

And then the important part: the agent is handed the **plan** plus an explicit
instruction not to report the operation as having happened.

```json
{
  "error": { "code": "approval_required", "message": "…" },
  "plan": {
    "summary": "reset Hard to HEAD",
    "steps": ["HEAD, the index AND the working tree are reset",
              "uncommitted changes to tracked files are DISCARDED"],
    "destructive": true
  },
  "next_step": "A human must approve `git.reset` before it can run. … you must not report this operation as having happened."
}
```

That exists because the realistic failure is not a malicious agent but a
confident one that describes work it was not allowed to do as though it were
done. A capability that cannot describe itself in advance gets no invented plan,
and both branches are covered by tests.

## Verified over a real pipe

```
initialize     → devd, protocol 2025-06-18, 5 tools
devd_groups    → 64 capabilities in 12 domains
devd_status    → git.status: ok, branch main, clean true
devd_invoke    → git.reset mode=hard: isError, approval_required, plan handed over
devd_doctor    → ok, 8 checks including git 2.46.0
```

Audit trail afterwards:

```
agent:claude-code  git.status   read         ok
agent:claude-code  git.reset    destructive  FAILED   <- the refusal
agent:claude-code  git.reset    destructive  ok       <- the plan, a dry run
```

`HEAD` was unchanged by the attempt.

## Tests

**169 tests pass** (up from 148), zero warnings. The 21 new ones are in
`devd-mcp`: the protocol, the tool surface and its non-growth, the forced actor,
discovery, and every refusal path — with a handler-incremented counter, so
"nothing ran" is a measurement rather than an inference.

## Still not built

The TUI. Services, sites, runtimes, DNS and TLS — the panels say so rather than
offering controls that do nothing.

## Install

```bash
git clone https://github.com/ianclemence/devd.git
cd devd
cargo build --release
./target/release/devd mcp --list
```

Requires Rust and `git` on `PATH`. Source archives only; no third-party
binaries.

See [`docs/mcp.md`](https://github.com/ianclemence/devd/blob/main/docs/mcp.md)
for the tool contract, and
[`docs/limitations.md`](https://github.com/ianclemence/devd/blob/main/docs/limitations.md)
for the honest gaps.
