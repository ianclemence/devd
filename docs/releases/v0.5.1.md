# v0.5.1 — a Windows installer, and one command to a working site

```text
devd-setup-0.5.1.exe   →  next →  install  →  finish
```

Double-click the installer, click through four pages, and the application
opens. There is no Rust toolchain, no environment variable, no PATH edit by
hand, and no administrator prompt.

## What the installer does

* Installs for the current user under `%LOCALAPPDATA%\Programs\devd`, so it needs
  no UAC prompt and cannot break another user's installation.
* Adds `devd` to the user's `PATH`, so a new terminal can run it.
* Creates Start Menu entries — **devd** opens the application, **devd terminal**
  opens a console with the environment check — and an optional desktop shortcut.
* Registers an uninstaller in *Apps & features*.
* On first start, runs `devd setup`, which downloads PHP, nginx and MariaDB
  (about 140 MB), starts them, creates a site, trusts the local certificate
  authority for the current user, and opens the application.

Uninstalling stops the application and its services, removes the files,
shortcuts, PATH entry and registry key, and **keeps your sites and data** in
`%LOCALAPPDATA%\devd`.

## `devd setup`

The same first-run path is a command:

```bash
devd setup          # installs and starts what is missing
devd setup --yes    # also trusts the certificate authority
```

It is idempotent: steps already done are reported and skipped. If ports 80 and
443 are held by another program, it moves the listeners to 8080 and 8443 and
persists the choice. The first site is published as `localhost`, which resolves
without a hosts-file entry and therefore needs no elevation; later sites use
`<name>.<test>` and `devd hosts sync`.

```console
$ devd setup --yes
note: port 80 is held by another program; using 8080 for HTTP
note: port 443 is held by another program; using 8443 for HTTPS
==> Runtime
    installing PHP (the vendor download is about 35 MB)
    installed php 8.5.11 at C:\Users\User\AppData\Local\devd\runtimes\php\8.5.11
==> Services
    installing nginx
    installed nginx 1.31.7 at C:\Users\User\AppData\Local\devd\services\nginx
    installing mariadb
    installed mariadb 13.0.2 at C:\Users\User\AppData\Local\devd\services\mariadb
==> Starting the stack
    3 service(s) running
==> First site
    created welcome in C:\Users\User\AppData\Local\devd\www\welcome (https://localhost:8443)
==> Certificate authority
    the devd certificate authority is trusted for this user

==> Ready
    site   https://localhost:8443
    app    devd ui
```

Verified on a clean machine state: the installed binary produced

```text
Protocol version: TLSv1.3
Peer certificate: CN=localhost
Signature type: ECDSA
Verification: OK
```

and `https://localhost:8443` answered `200 OK` from nginx with
`PHP 8.5.11 (cgi-fcgi)`.

## Fixed

* `www_root` was read only by the environment check; sites were always created
  under `<data>/www`. The setting is now honoured, including by the guard that
  protects `--delete-files`.
* `dns_mode` and `auto_start_services` were written to `settings.toml` and read
  by nothing. They are removed rather than left as switches that do nothing.
* A site published as `localhost` no longer warns that the name does not
  resolve, in either `site.create` or `site.list`.

## Release scripts

Local, by decision — there is no CI pipeline:

* `scripts/release-windows.ps1` — tests, build, smoke test, checksum.
* `scripts/release-linux.sh` — the same on Linux.
* `scripts/release-linux.ps1` — the Linux build from Windows through WSL or
  Docker.
* `scripts/release-installer.ps1` — builds this installer with NSIS.

See [`docs/releasing.md`](https://github.com/ianclemence/devd/blob/main/docs/releasing.md).
