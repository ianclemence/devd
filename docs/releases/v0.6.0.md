# v0.6.0 — the server dashboard

The application window now shows what is running, not only what is committed.

```text
 Overview   Sites   Services   Runtimes   Certificates   Hosts
            Projects   Capabilities   Activity   System
```

## What the window shows

**Overview** — one screen for the machine: a status banner with the running
count, HTTP and HTTPS ports and Start all / Stop all; four counters for
services, sites, PHP and certificates; and panels listing the sites, the
services with their controls, the hosts state and the certificate authority.

**Sites** — the table of sites with URL, PHP version, TLS, directory, an Open
button and Remove. Creating a site is a form: name, optional hostname, HTTPS,
and an optional database. Removal is destructive, so it raises the registry's
own plan and waits for approval.

**Services** — version, ports, state and PID for each service, with Start, Stop,
Restart, Logs (in a drawer) and Remove. Services that are not installed are
offered for installation; missing PHP points at the runtime page.

**Runtimes** — installed PHP, Node.js and Go, the primary PHP marked, with
"install latest", "use for new sites" and remove.

**Certificates** — the local authority and whether the operating system trusts
it, the two trust actions (per user, or machine-wide for an administrator),
removing trust, and the issued certificates with their chains and keys.

**Hosts** — the managed file, the pending additions and removals, the names
already published, and Sync behind the approval dialog.

## Trust state is asked, not remembered

The window used to remember locally whether you had trusted the authority. It
now asks: `tls.ca.status` checks the user and machine certificate stores with
`certutil` and reports both. The overview's notice and the Certificates page
therefore say what is true on this machine, not what this browser profile did
last week.

## The environment check was taking forty seconds

Every service liveness check and every port lookup started a `tasklist`
process. With three services and a few dozen listening sockets that was dozens
of process launches per page load. The same questions are now asked of the
kernel directly:

| | Before | After |
| --- | --- | --- |
| `devd doctor` | ~45 s | ~3 s |
| service list (window and CLI) | ~5 s | < 100 ms |
| port owner lookup | per port, with `tasklist` | one listener table per check |

The UI also stopped waiting for the doctor before drawing: session, then server
data, then the environment check.

## Design pass

Following Emil Kowalski's design engineering principles:

* buttons answer a press with `scale(0.97)` over 160ms, and every control has a
  visible `:focus-visible` ring;
* custom easing (`cubic-bezier(0.23, 1, 0.32, 1)`) replaces the built-in
  curves, which are too weak to read as intentional;
* the command palette appears with no animation at all — it is opened from the
  keyboard many times a day — while the approval modal keeps a short 200ms
  entrance, and nothing animates from `scale(0)`;
* numerals are tabular, so ports and counts do not shift as they change;
* the overview grid is three columns, then two, then one, without a layout
  breakpoint that hides information.

## Fixed

* The hosts block no longer proposes entries for `localhost` and its subdomains.
  They resolve without the file, so `hosts.show`, `hosts.sync` and the overview
  now agree with `site.create`.

## Still not built

Apache, Redis and Mailpit; a DNS server; SSH and deploy; the self-update check;
the in-app conversational agent. Service management remains Windows-only in this
release. The full list is in
[`docs/limitations.md`](https://github.com/ianclemence/devd/blob/main/docs/limitations.md).

## Install

Windows: run `devd-setup-0.6.0.exe` from the release page. Linux: build from
source, or produce an artifact with `scripts/release-linux.sh`. The installer
keeps your sites and data on uninstall.
