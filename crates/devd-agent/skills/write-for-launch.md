# Write for launch

Writes what people read about a product outside it: an announcement, release notes, landing copy, a launch script. Every claim is true and shown, and it reads like one person telling another.

## When to use

Anything public about the product. For documentation use `technical-writing`; for the voice use `plain-speech` and `unslop`.

## Procedure

1. **Find out what is true.** The product's own description and any slogan the owner chose: those are the slogans, and you add none. The real behaviour from the changelog, the code or a run.
2. **Name the reader and what they want to do.** Lead with what changes for them.
3. **Say it plainly.** What it does, for whom, what happens when they use it. Concrete nouns and numbers from a named source. Observational captions over claims.
4. **Cut what could be about any product.** Superlatives, fake urgency, aphorisms in tagline cadence, and the inflated adjectives `unslop` lists. Do not start a slogan with "Your". Leave out a version number or a platform unless it is the point.
5. **Check every claim** against the product. If you cannot show it, cut it or ask.
6. **End on the action:** the link, the command, the next step.

## Pitfalls

- A line that sounds like a generic AI product video.
- A number with no source.
- Inventing a tagline because the page feels empty. Ask the owner.

## Verification

Each claim in the report points at where it is true, and the text passes a read-through with `unslop`.
