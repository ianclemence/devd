# Choose by the outcome

Keeps the end state in view: what will be true when this is finished. Every step can run and the thing still not work.

## When to use

Planning a path, and again before you report anything done.

## Procedure

1. Write the outcome as a statement that is true or false ("a person can sign in and see their orders").
2. Choose the path to it with the least risk.
3. At the end check the outcome itself, not only that each step ran (`prove-it-works`).
4. Report the result for what it is: what is verified, what is not.

## Pitfalls

- A plan that is a list of activities with no stated result.
- Reporting completion of steps as completion of the goal.

## Verification

The outcome statement from step 1 is checked, and the report says whether it is true.
