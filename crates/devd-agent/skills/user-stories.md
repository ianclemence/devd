# User stories

A story is the smallest piece of work that changes what a person can do.

- Name the person (a role, not "the user"), the action and the reason.
- Write two to five acceptance criteria as observable outcomes: "after saving, the list shows the new name", not "saving works".
- Include the unhappy path in the criteria: what happens with empty input, no permission, no network, a duplicate.
- If a story needs more than a few days of work, or two unrelated criteria, split it.
- If two stories cannot be finished separately, they are one story.
- Order stories so that each one leaves the product usable.
